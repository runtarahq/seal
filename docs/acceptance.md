# seal: acceptance criteria and their tests

Each guarantee seal makes for its first release maps to the tests that show it.
Tests named `acceptance_*` are named after the criterion. A criterion marked
*planned* has no tests yet, because the code it describes does not exist.

| Criterion | Status | Tests |
|---|---|---|
| A process with only the sealing half and a public key cannot open anything | Done | `acceptance_a_sealing_only_build_cannot_open`; `seal_client_without_in_process_has_no_opening_code`; `the_webassembly_build_has_no_opening_code`; `scripts/wasm-roundtrip.sh` checks the module's exports |
| A value moved to another item, field or keyset does not open | Done | `acceptance_a_value_moved_to_another_item_does_not_open`, `_field_`, `_keyset_`; `changing_any_byte_of_the_binding_means_it_does_not_open`; `vectors/envelope.json` |
| A value from another record serves a request only if shared; a shared OAuth secret never serves a grant that acts as the platform | Done (library, and all three modes) | `a_value_from_another_record_is_refused_unless_shared`, `a_shared_value_is_refused_for_a_grant_its_rule_does_not_allow`; `a_tenant_uses_a_shared_platform_app_and_its_tokens_are_its_own`, `a_shared_secret_cannot_be_used_for_another_grant_or_with_a_value_from_another_tenant`, `a_caller_needs_the_platform_keyset_to_use_a_shared_value`; `a_jwt_bearer_grant_key_cannot_be_shared` |
| A changed policy does not open | Done | `acceptance_a_changed_policy_does_not_open`; `changing_any_byte_of_enc_or_ct_means_it_does_not_open` |
| A disallowed destination, method or path is refused with no DNS or provider traffic | Done | Library: `acceptance_a_disallowed_destination_method_or_path_causes_no_dns_or_connection`, `acceptance_a_malformed_request_causes_no_traffic_at_all`. All three modes: `acceptance_a_disallowed_destination_is_refused_and_nothing_is_sent` (no connection reaches the provider; DNS is counted in library mode only) |
| Redirects are returned; private addresses are refused unless allowed | Done | `acceptance_redirects_are_returned_not_followed` in all three modes; `acceptance_a_private_address_is_refused_after_dns_with_no_connection`; `every_range_is_classified_including_its_boundaries` |
| A webhook's signature is checked without the secret leaving seal; a truncated code never matches; a value sealed for sending verifies nothing, and a signing secret can be sent nowhere | Done (library, and all three modes) | `acceptance_a_webhook_signature_is_checked_without_the_secret_leaving_seal` in all three modes; `crates/seal-broker/tests/verify.rs`; `a_truncated_or_padded_code_never_matches`, `matches_the_published_test_vectors` |
| Named response fields never reach the caller in plaintext | Done for JSON, form and XML in all three modes | `acceptance_named_response_fields_are_sealed_and_usable_where_they_belong`, `named_xml_response_fields_are_sealed`; `a_value_made_by_an_attacker_cannot_strip_response_sealing`; `xml_that_could_hide_a_token_is_refused`; the `response_seal_*` fuzz targets, including `response_seal_xml` |
| A canary never appears outside a provider's own echo | Done in all three modes, after every test: the harness scans for every secret it sealed | `acceptance_a_canary_never_appears_in_logs_audit_or_errors`; `a_providers_own_echo_is_outside_the_guarantee` |
| 5 GB transfers, many in parallel, within a fixed memory limit | Done (library; plain HTTP, TLS, and RustFS with SigV4) | `acceptance_a_large_download_stays_within_the_limit`, `acceptance_a_large_upload_stays_within_the_limit`, `acceptance_large_s3_uploads_and_downloads_stay_within_the_limit` (chunked and caller hash), `acceptance_a_large_s3_multipart_upload_stays_within_the_limit`, `a_slow_caller_slows_the_provider_instead_of_growing_a_buffer`, `many_parallel_transfers_stay_within_a_limit_per_stream` (nightly) |
| All memory bounds filled at once stay under the ceiling | Done for the bounds that exist (nightly, Linux) | `acceptance_with_every_bound_filled_memory_stays_under_the_ceiling` fills streams, capped buffers, caller and provider connections, client-certificate identities, live keys and unknown keysets. The cost of each is measured by the other tests in `crates/seal/tests/memory.rs` |
| An over-cap sealed response is refused, and nothing of it reaches the caller | Done | `acceptance_an_over_cap_sealed_response_is_refused` in all three modes; library test checks no body bytes are counted |
| The same suite passes in all three modes; an unknown uid is refused | Done | `crates/seal/tests/modes.rs`, 24 tests in each mode; `acceptance_an_unknown_uid_is_refused`, `acceptance_a_certificate_with_an_unknown_subject_is_refused`. The broker's tests that count DNS lookups through fakes run in library mode only |
| Evicted keys reload; a restarted instance serves the same values | Done | `acceptance_evicted_keys_are_reloaded_on_next_use`; `acceptance_a_restarted_instance_serves_the_same_values` (keyring and binary) |
| A key added or deleted reaches all instances within `max_stale` | Done | `acceptance_a_rotation_on_one_instance_reaches_another_in_constant_use`, `acceptance_a_deleted_key_stops_opening_on_every_instance_within_max_stale`; with two binaries, `acceptance_a_rotation_and_a_deletion_on_one_instance_reach_another_within_max_stale` |
| A replaced client certificate does not reuse old connections | Done | `an_identity_reuses_its_connection_and_another_never_does`, `a_reloaded_key_never_reuses_the_old_connection`, `evicting_the_sealing_key_closes_the_identitys_connections`; `a_client_certificate_reaches_the_provider` in all three modes |
| SigV4 and Azure Shared Key work; caller-set signing headers are refused | Done | `crates/seal/tests/containers.rs` against RustFS and Azurite in all three modes; `the_aws_signing_test_suite_passes`, `seal_signs_as_the_aws_sdk_does`; `caller_set_amz_headers_are_refused_before_dns`, `the_date_and_authorization_are_seals_alone` |
| Every OAuth flow completes with sealed tokens; rotations continue | Done (mock server, all three modes) | `crates/seal/tests/oauth.rs`: one test per row of the table in [`oauth.md`](oauth.md), each with a canary scan of every issued token; `acceptance_rotating_refresh_tokens_continue_across_a_key_rotation`. Real providers: `crates/seal/tests/real_providers.rs`, gated on CI secrets |
| `tokio-postgres` works through `connect` on Postgres 14–18, with SCRAM with and without channel binding and a client certificate; another user or database is refused; a cancel reaches the right backend | Done (all three modes; nightly 1 GB `COPY`) | `crates/seal/tests/postgres.rs`, one scenario per version and mode: SCRAM with channel binding, a client certificate, MD5, cleartext, queries, transactions, `LISTEN`/`NOTIFY`, `COPY`, a refused user and database, a `pg_sleep` cancelled through another instance, logical and physical replication where allowed and refused otherwise. Servers over TLS always offer channel binding, so SCRAM without it is tested against an RFC 5802 server in `crates/seal-broker/src/pg/login/tests.rs`. `acceptance_a_gigabyte_copy_through_postgres_stays_within_the_limit` (nightly, Linux) |
